# 🧠 Раздел IX. Threat Modeling — моделирование угроз

Threat Modeling — один из самых важных навыков для архитектора, тимлида и AppSec-инженера.  
Это процесс выявления угроз *до* разработки, чтобы уязвимости не попадали в код в принципе.

В РФ моделирование угроз — обязательная часть:

- ГОСТ Р 56939–2024 (разработка безопасного ПО)  
- ФЗ-152 (модель угроз ПДн)  
- ФЗ-187 (КИИ: модель угроз обязательна)  
- Стандарты ЦБ РФ для финансовых организаций  

---

# IX-01. Что такое Threat Modeling

## Это — процесс поиска ответов на 4 ключевых вопроса:

1. **Что мы строим?**  
2. **Какие у нас активы и что мы защищаем?**  
3. **Какие угрозы возможны? Кто атакует?**  
4. **Какие меры защиты нужны?**

---

# IX-02. Основные подходы Threat Modeling  

1. **STRIDE** — модель угроз по типам атак  
2. **LINDDUN** — модель угроз приватности  
3. **PASTA** — риск-ориентированная методология (7 стадий)  
4. **Attack Trees** — построение дерева атак  
5. **Use/Abuse Cases** — анализ действий злоумышленника  
6. **VAST** — для крупных enterprise-систем  

---

# IX-03. STRIDE (основная модель)

STRIDE — фундаментальная модель Microsoft.

## 🎯 6 классов угроз:

| Буква | Угроза | Суть |
|------|--------|-------|
| **S** | Spoofing | Подделка идентичности |
| **T** | Tampering | Изменение данных |
| **R** | Repudiation | Отказ от действий |
| **I** | Information Disclosure | Утечка информации |
| **D** | Denial of Service | Блокировка работы |
| **E** | Elevation of Privilege | Повышение привилегий |

Эта модель обязательна для безопасной архитектуры.

---

# IX-04. LINDDUN (Privacy Threat Modeling)

Используется для анализа уязвимостей, связанных с персональными данными и приватностью.

## 7 типов угроз:

- Linkability  
- Identifiability  
- Non-repudiation  
- Detectability  
- Disclosure  
- Unawareness  
- Non-compliance  

Очень важна в РФ → по ФЗ-152.

---

# IX-05. PASTA — Process for Attack Simulation and Threat Analysis

7 стадий PASTA:

1. Определение целей бизнеса  
2. Декомпозиция приложения  
3. Анализ угроз  
4. Анализ уязвимостей  
5. Корреляция атак  
6. Моделирование вероятности и ущерба  
7. Формирование мер защиты

---

# IX-06. Data Flow Diagrams (DFD)

Основной инструмент Threat Modeling — DFD.

Типовые элементы:

- процессы  
- хранилища  
- внешние сущности  
- потоки данных  
- границы доверия (trust boundaries)

---

# IX-07. Attack Trees

Построение иерархической модели «как злоумышленник может достичь цели».

Пример цели:
```
Получить доступ к персональным данным
```

Дерево разветвляется до простейших действий.

# IX-08. Use/Abuse Cases

**Use Case:**  
«Пользователь оплачивает покупку»

**Abuse Case:**  
«Злоумышленник пытается изменить сумму без авторизации»

Используется в реальных командах РФ для поиска логических ошибок.

---

# IX-09. Threat Modeling в РФ: требования и практика

## ФЗ-152  
Для всех систем с ПДн → модель угроз обязательна.

## ФЗ-187  
КИИ требует модель угроз как часть документов ИБ.

## ГОСТ Р 56939–2024  
Требование моделировать угрозы *на стадии проектирования*.

## Банковский сектор  
ЦБ РФ требует формальную модель угроз.

---

# IX-10. Типовые ошибки в моделировании угроз

- Threat Modeling делается формально  
- берут шаблон и не анализируют бизнес  
- нет DFD  
- нет границ доверия  
- архитектура неполная  
- угрозы неправильно классифицированы  
- нет связи угроз → мер защиты  
- результат кладут «на полку»  

---

# IX-11. Как делать Threat Modeling правильно

1. Привлечь разработчиков, архитекторов, AppSec  
2. Нарисовать DFD  
3. Определить trust boundaries  
4. Разбить приложение на компоненты  
5. Пройтись по STRIDE для каждого потока  
6. Сопоставить угрозы → контрмеры  
7. Задокументировать  
8. Включить в архитектурные артефакты  
9. Обновлять при каждом изменении архитектуры

# IX-12. Практический cheat sheet Threat Modeling (используют банки и крупные компании)
