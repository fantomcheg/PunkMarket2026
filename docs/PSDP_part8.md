# VI‑01. Хранение токенов и чувствительных данных на фронтенде  

## 🎯 Цели  
- Понять, где безопасно хранить токены  
- Разобрать риски localStorage и sessionStorage  
- Узнать, почему токены должны жить в HttpOnly‑cookie  

---

## ❌ Нельзя хранить чувствительные данные:  
- в localStorage  
- в sessionStorage  
- в IndexedDB  
- в WebSQL  
- в JS‑объектах в памяти  

### Причина:  
XSS = полный доступ к этим хранилищам.

---

## ✔ Правильное хранение токенов  
- только **HttpOnly + Secure + SameSite cookie**  
- refresh‑token хранится только в cookie  
- access‑token короткоживущий

# VI‑02. Content Security Policy (CSP)  

CSP — мощный защитный механизм, который предотвращает выполнение произвольного JavaScript.

## Основные директивы:

### `default-src`  
Базовая политика загрузки ресурсов.

### `script-src`  
Управляет выполнением JS.

### `style-src`  
Управляет CSS.

### `img-src`, `font-src`, `connect-src`, `frame-src`  
Контроль загрузки ресурсов.

---

## CSP уровней:

### ⭐ Уровень 1 — базовая защита  
```
Content-Security-Policy: default-src 'self';
```

### ⭐⭐ Уровень 2 — защита от XSS  
```
script-src 'self' https://trusted.cdn.com 'nonce-XYZ';
```

### ⭐⭐⭐ Уровень 3 — максимальная защита  
```
script-src 'nonce-XYZ' 'strict-dynamic';
object-src 'none';
base-uri 'none';
```

---

## Нельзя использовать:  

```
unsafe-inline
unsafe-eval
*
```

# VI‑03. Clickjacking и защита интерфейсов  

## Атака  
Злоумышленник помещает ваш сайт в `<iframe>` и накладывает поверх свою кнопку.  
Пользователь думает, что нажимает UI сайта → на самом деле выполняет операцию злоумышленника.

---

## Защита:

### 1. Заголовки  
```
X-Frame-Options: DENY
frame-ancestors: 'none';
```

### 2. Фрейм‑детекция  
JS-скрипты, запрещающие отображение внутри iframe.

### 3. Многофакторная проверка действий  
На чувствительные операции → MFA/подтверждение.

# VI‑04. DOM‑based уязвимости и опасные JS‑API  

## Опасные функции:
- innerHTML  
- outerHTML  
- document.write  
- insertAdjacentHTML  
- setTimeout("string")  
- new Function()  
- eval()

---

## Проблема в React/Vue/Angular:  
- `v-html`  
- `dangerouslySetInnerHTML`

Любое использование этих API требует полноценной валидации + sanitize.

---

# VI‑05. Третьи стороны / виджеты / внешние скрипты  

## Риски:
- supply chain атаки,  
- изменение логики на клиенте,  
- кража токенов,  
- встраивание вредоносного JS (пример — атака на British Airways через сторонний скрипт).

---

## Защита:
- подключать только по SRI (Subresource Integrity):  
```
<script src="..." integrity="sha256-..." crossorigin="anonymous"></script>
```
- использовать CSP с nonce  
- минимизировать внешние скрипты  
- не доверять сторонним рекламным/трекерам  

---

# VI‑06. Безопасность SPA (React/Vue/Angular)  

SPA страдают от:

- DOM‑XSS  
- небезопасного роутинга  
- статической генерации ошибок  
- хранения токенов в localStorage  
- отсутствия серверных проверок  

---

## Рекомендации:
- хранить токены только в cookie  
- все проверки прав выполнять на backend  
- запрещать HTML‑рендер из API  
- не доверять данным из URL  
- использовать Sanitizer API  

---

# VI‑07. WebAssembly (WASM)  

WASM создаёт новые поверхности атаки:

- memory corruption  
- sandbox escape  
- непроверенные модули  
- смешивание WASM и JS  

---

## Защита:
- загружать WASM только из доверенных источников  
- применять CSP (`script-src 'wasm-unsafe-eval'` запрещён!)  
- sandboxed environment  

---

# VI‑08. Браузерные расширения (Chrome/Firefox)  

## Опасности:
- могут читать всю страницу  
- могут передавать данные злоумышленнику  
- многие расширения в РФ использовались для утечек ПДн  

---

## Защита:
- политика «минимум расширений»  
- аудит установленных расширений в корпоративной среде  
- использование Manifest V3  

---

# VI‑09. Referrer Policy  

Неправильная политика → утечка токенов и чувствительных URL в сторонние домены.

## Правильно:
```
Referrer-Policy: no-referrer
```

или  
```
strict-origin
```

---

# VI‑10. Защита от браузерных атак  

## Основные угрозы:
- autofill hijacking  
- clickjacking  
- UI redress  
- tabnabbing  

## Защита:
- `noopener noreferrer`  
- Content Security Policy  
- безопасные формы ввода
