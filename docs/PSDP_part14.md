# 🔑 Раздел XIV. Secrets Management  
## Управление секретами в приложениях и инфраструктуре

Secrets Management — один из самых критичных разделов.  
80% крупных утечек в РФ происходят из‑за компрометации секретов:

- токенов в репозиториях,  
- открытых .env,  
- утекших приватных ключей,  
- неправильных прав доступа в CI/CD.  

---

# XIV-01. Что считается секретом  

- пароли  
- API ключи  
- приватные ключи  
- OAuth токены  
- JWT signing keys  
- refresh tokens  
- SSH ключи  
- токены внешних сервисов  
- ключи БД  
- ключи криптографии (AES/RSA/ГОСТ)

---

# XIV-02. Где нельзя хранить секреты  

### ❌ Нельзя хранить:  
- в Git  
- в .env на сервере  
- в docker-compose.yml  
- в Docker image  
- в JS-коде front-end  
- в мобильных приложениях  
- в почте / Slack  
- в Jira / Confluence  

---

# XIV-03. Где можно хранить секреты (правильно)

### ✔ Vault-системы:
- Hashicorp Vault  
- AWS/Yandex/GCP Secrets Manager  
- Kubernetes Secrets + encryption + sealed-secrets  
- CI/CD internal secrets  

### ✔ Безопасная доставка:
- через sidecar контейнер  
- через encrypted env  
- через token-based access  

---

# XIV-04. Ротация секретов  

Секреты должны:
- регулярно обновляться  
- автоматически ревокироваться  
- иметь TTL  
- не использоваться повторно  

---

# XIV-05. Secret Scanning  

Необходим на pre-commit/CI:

- Gitleaks  
- Trufflehog  
- GitGuardian  
- built‑in GitHub secret scanning  

---

# XIV-06. Российские требования  

## ФЗ-152

## ФЗ-187

## ГОСТ Р 56939–2024

# 🧬 Раздел XV. Криптография для разработчиков  
## Основы для правильного, безопасного применения криптографии в коде

Этот модуль НЕ учит математике криптографии.  
Он объясняет, **как не сломать безопасность продуктом**, используя криптографию.

---

# XV-01. Хэширование  

## ❌ Нельзя использовать:
- MD5  
- SHA1  
- CRC32  
- Base64 как «шифрование» (!)  

## ✔ Правильно:
- SHA256  
- SHA512  
- ГОСТ Р 34.11–2012 (Стрибог)  
- PBKDF2  
- bcrypt  
- Argon2id  

---

# XV-02. Хранение паролей  

Пароли хранятся только в виде:  
```
Argon2id(hash, salt, memory=256MB, iterations=3)
```

Или:
- bcrypt cost ≥ 12  
- PBKDF2 iterations ≥ 310k  

---

# XV-03. Симметричное шифрование  

Используем:
- AES‑256‑GCM  
- ГОСТ 28147‑89 в режиме Кузнечик  

Нельзя использовать:
- ECB режим  
- самописные шифры  

---

# XV-04. Асимметричная криптография  

Используем:
- RSA‑2048/4096  
- ECDSA P‑256  
- ГОСТ Р 34.10–2012  

Нельзя:
- ключи < RSA‑1024  
- самописные реализации  

---

# XV-05. Управление ключами  

Ключи должны:  
- храниться в защищённом хранилище  
- иметь срок жизни  
- иметь строгий доступ  
- быть версионированы  
- не попадать в логи  

---

# XV-06. TLS / HTTPS  

## Минимальные требования:
- TLS 1.2+  
- запрещено: TLS 1.0, SSLv3  
- шифры: ECDHE + AES‑GCM  
- HSTS включён  
- редиректы на HTTPS  

---

# XV-07. Подписи и целостность  

Используем:
- HMAC‑SHA256  
- RSA/ECDSA  
- ГОСТ Р 34.11/34.10  

---

# XV-08. Генерация случайных чисел  

❌ Нельзя:  
- Math.random()  
- rand()  

✔ Нужно:  
- /dev/urandom  
- crypto.getRandomValues  
- libsodium  

---

# XV-09. Типичные крипто‑ошибки разработчиков  

- хранение паролей в plaintext  
- отсутствие соли  
- использование JWT без exp  
- использование RSA неправильной длины  
- использование MD5 «для скорости»  
- хранение ключей в репозитории  
- применение “шифрования” через Base64
