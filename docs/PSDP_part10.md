# ⚙️ Раздел VIII. DevSecOps, CI/CD и автоматизация безопасности

Этот раздел посвящён тому, как встроить безопасность в процесс разработки так, чтобы:

- разработчики не страдали,  
- продукт не замедлялся,  
- безопасность была автоматизирована,  
- уязвимости находились *до* релиза,  
- соответствие требованиям РФ (152-ФЗ, 187-ФЗ, ГОСТ 56939–2024, отраслевые стандарты ЦБ) выполнялось автоматически.

DevSecOps — это не «ещё один человек», а **архитектура процессов + технологии + автоматика**.

---

# VIII-01. Принципы DevSecOps  

## 🎯 Главная цель  
Сделать безопасность частью CI/CD, а не отдельным ручным блоком.

## 📌 Основные принципы:

### 1. Security as Code  
Правила, политики, проверки — в репозитории.

### 2. Automate Everything  
Любая проверка, которая может быть автоматизирована, должна быть автоматизирована.

### 3. Shift Left  
Чем раньше найдена уязвимость, тем дешевле её исправление.

### 4. Continuous Security  
Проверки запускаются на каждом этапе.

### 5. Developer Friendly  
Проверки **не должны мешать разработчику**.

# VIII-02. Архитектура безопасного CI/CD  

## Многоуровневый конвейер безопасности:

### **1. Pre-commit уровень**
- Secret-scanning  
- Linting безопасного кода  
- Форматирование  
- Проверка зависимостей (SCA)  

### **2. Build-уровень**
- SAST  
- SCA  
- SBOM генерация  
- Проверка контейнеров  

### **3. Test-уровень**
- DAST  
- API security tests  
- integration + security unit tests  

### **4. Pre-production**
- IaC scanning  
- Kubernetes security checks  
- SAST повторно (incremental)  
- Проверка конфигураций  

### **5. Production**
- RASP  
- мониторинг аномалий  
- WAF  
- журналирование и алерты  
- auto-blocking политики

# VIII-03. Типы автоматизированных проверок  

## 1. SAST — статический анализ кода  
Ищет:
- XSS  
- SQLi  
- SSRF  
- insecure deserialization  
- hardcoded secrets  
- path traversal  

## 2. SCA — анализ зависимостей  
- CVE  
- лицензии  
- компрометированные пакеты  
- подмены библиотек  

## 3. DAST — динамический анализ  
Ищет:
- XSS  
- SQLi  
- открытые панели  
- misconfiguration  

## 4. IAST  
Комбинация SAST+DAST в рантайме.

## 5. RASP  
Защита в рантайме (runtime application self-protection).

# VIII-04. Secret Scanning  

Одна из самых частых проблем в РФ — утечки секретов из репозиториев.

Ищем:
- ключи к БД  
- токены OAuth  
- API keys  
- пароли  
- приватные ключи  

Используем:
- Gitleaks  
- TruffleHog  
- GitGuardian  

---

# VIII-05. Supply Chain Security и SBOM  

## SBOM (Software Bill of Materials)
Список всех зависимостей, библиотек и компонентов продукта.

Требуется:
- ГОСТ Р 56939–2024  
- NIST SSDF  
- банки и госы требуют SBOM в тендерах  

---

# VIII-06. Контейнерная безопасность  

Проверки:
- минимальный образ  
- non-root user  
- отсутствие лишних capabilities  
- seccomp  
- AppArmor  
- read-only root filesystem  
- ограниченные сети  

---

# VIII-07. Kubernetes Security  

Проверяем:
- RBAC  
- PSP/OPA/Gatekeeper  
- NetworkPolicy  
- Secrets encryption  
- ограниченные namespaces  
- безопасность ingress  

---

# VIII-08. Workflow для DevSecOps  

## 1. Для разработчика  
- pre-commit hooks  
- IDE linting  
- local SAST  
- быстрые проверки  

## 2. Для CI/CD  
- SAST+SCA на pull request  
- DAST на staging  
- блокировка релиза при критичных уязвимостях  

## 3. Для эксплуатации  
- мониторинг  
- алерты  
- автоматический revoke токенов  
- оповещение AppSec

### 🟦 «Низкие → в течение 30 дней»

# VIII-10. DevSecOps в российских компаниях  

## Банковский сектор:  
- обязательная проверка всех систем на уязвимости  
- автоматизация по требованиям ЦБ РФ  
- управление ключами  
- журналирование  

## Телеком/крупный enterprise:  
- обязательная интеграция SAST/DAST  
- безопасное хранение секретов  
- механизмы auto-block в периметре  

## Гос/КИИ:  
- обязательная проверка на стадии эксплуатации  
- строгие требования к криптографии  
- контроль безопасной поставки ПО

# VIII-11. Метрики DevSecOps  

- время от коммита до обнаружения уязвимости  
- MTTR (mean time to remediation)  
- покрытие SAST  
- покрытие SCA  
- процент блокирующих уязвимостей  
- соответствие SLA по фиксам  
- SBOM coverage  
- количество нарушений политик
