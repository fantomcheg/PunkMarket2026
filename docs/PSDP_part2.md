## Файл 2/15 — Общая структура программы и дорожная карта

Этот файл описывает общую структуру курса, основные роли и уровни, а также даёт обзор всех разделов, которые далее будут раскрыты в отдельных частях.

---

## 1. Целевая аудитория и уровни

### 1.1. Для кого эта программа

- Разработчики (backend, frontend, full‑stack)
- Тимлиды и техлиды
- Архитекторы
- DevOps / SRE / инженеры сопровождения
- Внутренние «security champions» в командах разработки

### 1.2. Уровни прохождения

Каждый раздел программы помечен предполагаемым уровнем:

- 🟢 **Базовый (L1)** — джуны / разработчики без опыта в AppSec  
- 🟡 **Продвинутый (L2)** — миддлы, тимлиды  
- 🔴 **Экспертный (L3)** — синьоры, архитекторы, DevSecOps, AppSec-инженеры  

---

## 2. Российский контекст и регуляторика

Во всех модулях курса учитываются требования и реалии РФ:

- **ФЗ‑152 «О персональных данных»**  
- **ФЗ‑187 «О безопасности критической информационной инфраструктуры»**  
- Постановления Правительства РФ и приказы ФСТЭК/ФСБ по защите информации  
- Требования **ЦБ РФ** к защищённости финансовых организаций  
- **ГОСТ Р 56939‑2024** «Разработка безопасного программного обеспечения. Общие требования»  
- Внутренние стандарты крупных российских компаний (банки, телекома, госсектор)  

Каждый крупный раздел будет сопровождаться блоком:

> «Как это связано с 152‑ФЗ / 187‑ФЗ / ГОСТ / ФСТЭК в реальных проектах».

## 4. Учебные треки по ролям

Эта же программа может использоваться по‑разному для разных ролей.

### 4.1. Трек «Разработчик / Тимлид»

Фокус:

- Разделы I–VI, X, XIV, XV, XVIII (в базовом объёме)
- Цель — научить писать безопасный код, читать отчёты и устранять уязвимости.

Рекомендуемая последовательность:

1. I. Основы
2. II. OWASP Top‑10 Core
3. III. Аутентификация и контроль доступа
4. IV. Современные протоколы и API
5. V. Advanced Web Exploitation
6. X. API Security
7. XIV–XV. Secrets & Crypto (в практической части)
8. XVIII. Security‑тестирование (чтение отчётов SAST/DAST/пентеста)

### 4.2. Трек «Архитектор / Tech Lead»

Фокус:

- Всё, что у разработчика, **плюс**:
- VII. Security‑фреймворки и ГОСТ 56939‑2024
- IX. Threat Modeling
- XII. Cloud/Kubernetes
- XVII. Zero Trust
- XXI. Secure architecture patterns

Задача — уметь проектировать безопасную архитектуру под требования бизнеса и регуляторов.

### 4.3. Трек «DevSecOps / AppSec»

Фокус:

- VIII. DevSecOps и CI/CD Security
- X. API Security
- XII. Cloud/K8s
- XIII. Supply Chain / SBOM / SLSA
- XIV. Secrets Management
- XVIII–XIX. Тестирование, логирование, IR
- XXI. WAF и защитные механизмы

Задача — строить автоматизированный конвейер безопасности вокруг разработки.

### 4.4. Трек «Security Champion в команде разработки»

Комбинированный трек:

- Весь путь разработчика
- Базовые части DevSecOps и Threat Modeling
- Блоки по security‑культуре и обучению других

## 5. Формат уроков и артефактов

Каждый урок теоретической части (то, что мы генерируем сейчас):

- оформлен в Markdown,
- содержит:
  - вводную часть и цели;
  - основные понятия;
  - подробные разборы типичных кейсов;
  - связь с российской регуляторикой (где применимо);
  - список типичных ошибок разработчиков;
  - краткий чек‑лист для самопроверки кода.

Практика, вопросы, лабораторные, тесты — будут подключаться отдельно (в твоей платформе Punkration / Bug2Lab) и здесь **специально не описываются**, чтобы этот файл выполнял роль **теоретического справочника и основы для конспектов**.
