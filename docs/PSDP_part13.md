# 📱 Раздел XI. Mobile Security (Android / iOS)

Мобильные приложения — одна из самых частых точек атак в финтехе, госуслугах и телекомах.  
Уязвимости в мобильных API, неправильное хранение токенов, отсутствие pinning — главные причины ATO и фрода.

---

# XI-01. Архитектура мобильной безопасности

Основные компоненты:

- клиентское приложение (Android/iOS)  
- API сервер  
- хранилище токенов  
- sandbox приложения  
- keychain / keystore  
- протокол аутентификации  

---

# XI-02. Основные угрозы мобильных приложений

### 1️⃣ MITM (Man-in-the-Middle)  
Перехват трафика → кража токенов, паролей, операций.

### 2️⃣ Reverse Engineering  
APK можно декомпилировать → увидеть логику, ключи.

### 3️⃣ Root/Jailbreak  
Снижается защищённость устройства.

### 4️⃣ Inter-process Injection  
Инъекция фальшивых интентов.

### 5️⃣ Неправильный контроль сессий  
Использование long-lived токенов.

---

# XI-03. Защита мобильных приложений

### ✔ Certificate Pinning  
Приложение принимает только сертификат сервера → MITM невозможен.

### ✔ HttpOnly-cookie для токенов API  
При использовании WebView или embedded login.

### ✔ Keystore / Keychain  
Безопасное хранение секретов.

### ✔ Обфускация кода  
Защита от реверс-инжиниринга.

### ✔ Root/Jailbreak detection  
Блокировка опасных устройств.

---

# XI-04. Безопасность мобильных API

- обязательный rate limiting  
- device fingerprint  
- контроль аномалий  
- токены короткого срока жизни  
- MFA  
- защита от replay  

---

## ЦБ РФ  
— жесткие требования к мобильным приложениям банков  
— контроль MITM  
— контроль root  
— обязательное журналирование  

## ФЗ-152  
Хранение ПДн только в защищённых хранилищах.

Компоненты:

# XII-03. Kubernetes Security Essentials

### ✔ RBAC  
Только необходимые роли.

Разделение окружений.

### ✔ NetworkPolicy  
Запрет межсервисного трафика по умолчанию.

### ✔ Secrets encryption  
Хранение секретов зашифрованно.

### ✔ PodSecurity (OPA/Gatekeeper)

### ✔ Resource limits  
Защита от DoS.

# XII-04. Container Security

## Правильные практики:

- minimal base image  
- non-root user  
- read-only rootfs  
- drop capabilities  
- seccomp  
- apparmor  
- ограниченные volume mounts

# 🔗 Раздел XIII. Supply Chain Security, SBOM, SLSA, SCA

---

# XIII-01. Почему supply chain — критическая тема

Примеры атак:
- SolarWinds  
- компрометация NPM пакетов  
- трояны в PyPI  
- атаки на GitHub Actions  

В РФ supply chain обязателен по:
- ГОСТ Р 56939–2024  
- требованиям ЦБ РФ  
- моделям NIST SSDF  

---

# XIII-02. SBOM (Software Bill of Materials)

SBOM описывает:
- все зависимости  
- версии  
- лицензии  
- поставщиков  

Используется для:
- сертификации  
- прохождения аудита  
- требований заказчиков  

---

# XIII-03. SLSA (Supply-chain Levels for Software Artifacts)

Уровни SLSA:

1. **SLSA 1** — базовые процессы  
2. **SLSA 2** — сборка с проверками  
3. **SLSA 3** — верифицируемая сборка  
4. **SLSA 4** — максимальный уровень доверия  

---

# XIII-04. SCA — анализ зависимостей

Ищет:
- CVE в зависимостях  
- злонамеренные пакеты  
- уязвимые версии библиотек  

Инструменты:
- Dependabot  
- Snyk  
- GitLab SCA  
- Trivy  

---

# XIII-05. Защита цепочек поставок

- минимизация зависимостей  
- верификация поставщиков  
- использование lockfiles  
- CI/CD изолирован от интернета  
- подпись артефактов  
- контроль доступа  
- мониторинг изменений  

---

## ЦБ РФ  
Требует управление зависимостями и контроль уязвимостей.
